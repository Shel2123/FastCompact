# Этап 5: круговое меню в продукте

Меню рисует `RadialMenu` (`crates/orbit-macos/src/ui/radial_panel.rs`) за портом `MenuView`: `present`, `highlight`, `hide`. Решения взяты из spike ([`spike-5.md`](spike-5.md)); код spike (`examples/spike_ui/`) остаётся справкой до приёмки этапа. Ядро (`orbit-domain`, `orbit-app`, `orbit-runtime`) не менялось.

Вид не принимает ввод: указатель приходит из tap, попадание считает контроллер (`MenuGeometry::hit`). В простое у вида нет таймеров, наблюдателей и мониторов событий.

## Что в этапе, а что нет

| Есть | Нет (открыто) |
|---|---|
| Стеклянный диск `NSGlassEffectView`, 9 секторов, SF Symbols | Имя файла в меню (`MenuModel.title`): пункт MVP «меню с именем объекта» **не выполнен**, решение пользователя |
| Палитра по теме, иконка на подсветке белая или чёрная по контрасту | Анимация появления: меню появляется сразу; пружина осталась в spike |
| Подсветка 70 мс, недоступный сектор тускло, «Отмена» красная | Increase Contrast |
| Reduce Transparency: непрозрачный диск | Пересчёт цветов при смене темы под **открытым** меню |
| Центр из `MenuModel.center`; диск следует за окном, если AppKit сдвинул его | Форма параметров, прогресс, уведомления (этапы 6–11) |

## Устройство

| Файл (`crates/orbit-macos/src/ui/`) | Что |
|---|---|
| `radial_panel.rs` | `RadialMenu: MenuView`, `Background`, окно (`NSPanel`: borderless, nonactivating, `NSPopUpMenuWindowLevel`, не принимает мышь, не key), фоновый вид-диск, тема, чтение акцента и красного |
| `radial_view.rs` | `Surface`: слои (плоский диск, 9 `CAShapeLayer`, 9 иконок с маской-символом), `reset`, `highlight`, `place_disc`, `drawable`; без `NSView` |
| `menu_session.rs` | чистый автомат: открыто ли меню и что подсвечено; решает, что игнорировать |
| `palette.rs` | цвета в sRGB без AppKit, выбор чернил по контрасту WCAG (≥ 3:1) |
| `symbols.rs` | имена SF Symbols и их отрисовка в `CGImage` |
| `logging.rs` | `LoggingMenuView` остался как **деградированный режим**: если `RadialMenu::new` вернул ошибку, `mac_platform.rs::views()` пишет `error!` и ставит его; меню не рисуется, а жест при этом выполнится вслепую |

Размеры: диск 220 pt (радиус 110), окно 240 pt (поля `MARGIN` = 10 pt).

### Контракт `MenuView`

| Вызов | Состояние | Результат |
|---|---|---|
| `present` | закрыто | показать |
| `present` | открыто | заменить без `orderOut`; подсветка сброшена |
| `highlight` | закрыто | игнорируется (`debug!`) |
| `highlight` | то же значение | ничего |
| `highlight` | слот вне меню | `warn!`, ничего |
| `hide` | закрыто | ничего |
| `hide` | открыто | `orderOut` |
| `present` с геометрией без сектора на каждый пункт | `error!`, панель прячется, сессия закрывается (защитная ветка: контроллер строит `standard()`) |
| `present` с другой геометрией | слои и окно собираются заново, `warn!` |

### Правило про анимации

Неявные анимации разрешены только в `Surface::highlight` (70 мс). Всё остальное (сброс, перекраска, смена масштаба, положение диска) идёт в `CATransaction` с `setDisableActions(true)`; `reset` перед этим снимает анимации у всех секторов и иконок. В debug-сборке после показа считается число слоёв с анимациями: при ненулевом значении в лог идёт `warn!`.

### Положение и масштаб

1. Окно ставится в `center − side/2`, повторного зажима по экрану нет: центр уже посчитан `place_menu` в контроллере.
2. Читается фактический `frame()`. Если окно оказалось дальше 0,5 pt от места, весь диск (фон и содержимое как одно целое) сдвигается в окне на ту же величину обратно (`place_disc`), в логе `warn!` с `shift` и `placement`. Сдвиг больше `MARGIN` не компенсируется целиком: диск не выходит за окно, остаток в `residual`.
3. Масштаб читается после `setFrameOrigin` и ещё раз после `orderFrontRegardless`. Если значения разные (окно, которое не на экране, может не знать свой дисплей), слои перекрашиваются с новым масштабом. Иконки хранятся для двух последних масштабов.

### Запасные фоны

`NSGlassEffectView` есть с macOS 26. Если класса нет, берётся `NSVisualEffectView` (HUD, закреплён на теме приложения), в логе `info!`. Для проверки на машине со стеклом (debug-сборка): `ORBIT_DEBUG_MENU_BACKGROUND=glass|vibrancy|plain`. При Reduce Transparency и фоне `plain` поверх фона включается непрозрачный диск (`Palette::disc`, альфа 0,96); фон при этом не скрывается: слои лежат внутри фонового вида, и `setHidden` спрятал бы их вместе с ним (так было в spike, где Reduce Transparency не прогонялся).

### Debug-переключатели (только debug-сборка)

| Переменная | Значение |
|---|---|
| `ORBIT_DEBUG_MENU_BACKGROUND` | `glass`, `vibrancy`, `plain`; другое значение игнорируется с `warn!` |
| `ORBIT_DEBUG_MENU_SHIFT` | `dx,dy` в целых пунктах: окно ставится дальше от нужного места на столько, чтобы увидеть компенсацию; неверное значение игнорируется с `warn!` |

Запуск: `ORBIT_SIGN_IDENTITY="Apple Development: …" scripts/bundle.sh` (с ad-hoc подписью Accessibility сбрасывается после пересборки, tap ждёт разрешения). Остальные `ORBIT_DEBUG_*` передаются через `open --env`.

## Известные ограничения

- Динамические цвета (акцент, красный) читаются для внешнего вида приложения, а не стеклянного вида; на практике они совпадают, отдельно не проверялось.
- Тема, сменённая под открытым меню, не подхватывается до следующего показа.
- Первая подсветка после `present` (курсор уже над сектором) идёт переходом 70 мс, как любая другая.
- Haptics не проверялись.
