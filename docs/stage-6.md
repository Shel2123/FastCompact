# Этап 6: мгновенные действия

Сектора «Путь», «Reveal» и «Сведения» выполняют действие, уведомления видны на экране. Раньше на месте портов `Shell` и `Feedback` стояли заглушки `LoggingShell` и `LoggingFeedback`: они только писали в лог.

Ядро изменилось в двух местах:
- `Notice::PathCopied` (`orbit-app/src/messages.rs`). Его отправляет runtime после успешного `WriteClipboard` (`orbit-runtime/src/effects.rs`), потому что только платформа знает, удалась ли запись. Успешный Reveal тоста не даёт: результат и так виден в Finder.
- Сбой `Shell` runtime сам превращает в `Notice::ActionFailed` и передаёт в `Feedback` (`shell_failed`). Контроллер о сбое не узнаёт: от действия ничего в его состоянии не зависит.

`ScreenRect::contains` и `ScreenRect::distance_to` (`orbit-domain/src/geometry.rs`) стали pub.

План этапа сохранился не полностью: план шага 5d лежит в [`plans/stage-6-5d-folder-size-speed.md`](plans/stage-6-5d-folder-size-speed.md), остальное собрано из кода и коммитов `d293fbd`…`213a82d`.

### Контракт `Shell`

- В буфер кладётся только строка пути (`NSPasteboardTypeString`), без file URL. Путь не в UTF-8 даёт ошибку, буфер не трогается.
- Reveal выполняется через `NSWorkspace::selectFile_inFileViewerRootedAtPath`; ответ `false` становится ошибкой. Symlink Finder выделяет сам, без перехода по ссылке.
- Каждый вызов AppKit идёт внутри `objc2::exception::catch`. Буфер обмена сообщает о части сбоев исключением `NSPasteboardCommunicationException`, а исключение Objective-C, дошедшее до кода Rust, завершает процесс. Пойманное исключение становится `ShellError`. Фича `exception` у `objc2` добавила транзитивные зависимости `objc2-exception-helper` и `cc`.
- Файловой системы `Shell` не касается: существует ли файл, сообщает Finder.

### Тост

- Окно одно на всё время работы приложения; новый тост заменяет тот, что на экране.
- Таймер один (`NSTimer`). Новый тост сначала отменяет таймер прежнего (`invalidate`), потом ставит свой: длинный таймер ошибки не спрячет раньше времени более поздний короткий тост. Таймер существует, только пока тост на экране.
- Успех держится 1,5 с, ошибка 4 с (`notice_text.rs`).
- Окно не становится key и пропускает клики в приложение под ним.
- `MoveToActiveSpace | FullScreenAuxiliary`: тост остаётся на рабочем столе, где показан, и виден поверх полноэкранного окна.

### Размещение (`place_panel`)

1. Экран выбирается по `frame`: строка меню и Dock лежат на экране, но вне `visible`. Интервалы полуоткрытые. Курсор вне всех экранов → ближайший экран, при равенстве первый (основной).
2. Область — `visible` выбранного экрана без поля `SCREEN_MARGIN` (8 pt) с каждой стороны. Панель не больше области.
3. Панель встаёт справа снизу от курсора на расстоянии `GAP` (12 pt). Если не помещается, слева или сверху. Затем сдвигается внутрь области.

### Что закрывает панель (`CloseRule`, `CloseWatch`)

- Пока панель на экране, работают два монитора `NSEvent` с маской `LeftMouseDown | RightMouseDown | OtherMouseDown | KeyDown | FlagsChanged`:
  - global — события других приложений;
  - local — события самого Orbit (его значок в строке меню), которые global не видит. Local возвращает событие без изменений.
- Watch стартует только с обоими мониторами: с одним панель осталась бы на экране после клика, который должен её закрыть. Не удалось поставить оба → панель не показывается.
- Закрывают клик, клавиша и **новый** модификатор: Shift, Control, Option, Command. Отпускание модификатора не закрывает: панель появляется в конце жеста, когда часть модификаторов хоткея ещё зажата. Caps Lock и Fn не учитываются.
- `CloseRule` помнит последние увиденные модификаторы и обновляет их на каждом `FlagsChanged`, в том числе проигнорированном. Начальное значение читается **после** регистрации мониторов: иначе нажатие между чтением и регистрацией потерялось бы.
- Мониторы снимаются всегда отложенно (`remove_later`), не изнутри их собственного обработчика. В простое мониторов нет.

### Панель «Сведения»

- Показ идёт транзакцией в `MacFeedback::show_info`: `InfoPanel::prepare` раскладывает лист и находит рамку, затем ставится `CloseWatch`, и только потом `InfoPanel::show` выводит окно. При любом сбое `give_up` прячет панель и снимает watch: панели, которую нечем закрыть, на экране не остаётся.
- `ShowInfo` открывает панель для любой цели, которую вернул resolver. `SizeJob` запускается только для Directory и Package.
- Повторный показ заменяет панель: прежние watch и подсчёт останавливаются, как только их отпускают, и новую панель не трогают.
- Ширина целевая 360 pt; на экране уже этого она равна ширине области. Высота считается по содержимому через `sizeThatFits`: `fittingSize` занижает высоту многострочного текста.
- Путь занимает не больше 6 строк (`PATH_LINES`); более длинный теряет середину, начало и имя в конце остаются. AppKit не обрезает середину текста с переносом, поэтому обрезка своя, двоичным поиском.

Строки (`info_sheet`, своего I/O нет, сведения на момент жеста):

| Строка | Когда | Значение |
|---|---|---|
| Kind | всегда | File, Folder, Package, Symbolic link: классификация Orbit, не тип документа из Finder |
| Size | файл | логический размер `FileVersion.size`: `NSByteCountFormatter` (file style) и точное число байт, как в Get Info |
| Size | папка, пакет | место на диске; сначала «Calculating…», потом нарастающая сумма, потом итог |
| Modified | всегда | `NSDateFormatter` medium/short в локали пользователя |
| Image | изображение | формат и `W × H`; пока не заполняется (этап 8) |
| Path | всегда, последней | `to_string_lossy` |

У symlink строки Size нет.

### Размер папки

- Размер — место на диске, как у `du -x`: `ATTR_FILE_ALLOCSIZE` или `st_blocks × 512`. Разреженный файл считается занятыми блоками, клоны APFS — каждый целиком. Логический размер отменён 2026-11-26: разреженный `Docker.raw` (1,1 ТБ логически, 9,3 ГБ на диске) давал домашней папке «At least 1.35 TB» на диске 460 ГБ.
- Блоки самих каталогов не считаются, поэтому с `du -skx` совпадение примерное.
- Symlink считается своими блоками, по ссылке обход не идёт. Hard link (`nlink > 1`) считается один раз по `(dev, ino)`.
- Другие тома не обходятся: граница проверяется по `fstat` открытой папки.
- Рабочих потоков до 4 (`MAX_WORKERS`, но не больше `available_parallelism`), очередь папок общая. Если не создался ни один поток, обход идёт в вызывающем потоке без промежуточных сумм.
- Папка читается через `getattrlistbulk`. Если вызов упал до первой записи, папка читается `read_dir` с начала. Если упал позже, набранное остаётся, а папка идёт в «не прочитано».
- iCloud не скачивается: dataless-папки не открываются, рабочие потоки включают `setiopolicy_np` (`MATERIALIZE_DATALESS_FILES_OFF`). Если вызов не прошёл, в логе `warn!`, и защищает только проверка флага `SF_DATALESS`.
- Что не прочиталось, не входит в сумму, и строка пишет «At least …»: подсчёт неполный.
- Промежуточная сумма приходит раз в 250 мс (`UPDATE_EVERY`) через main queue. Папка, посчитанная быстрее, сразу показывает итог.
- Закрытие или замена панели поднимает `cancel` на main. Каждая запись в строку сначала его проверяет, поэтому поздний итог не попадёт в следующую панель. Обход останавливается на следующей записи, в логе `folder size cancelled`. Блокирующее чтение (медленный сетевой том) сначала дожидается конца.
- Последний `Arc<MainThreadBound>` всегда освобождается на main: drop вне main у `dispatch2` синхронно ждал бы main.

Замеры и устройство обхода описаны в [`plans/stage-6-5d-folder-size-speed.md`](plans/stage-6-5d-folder-size-speed.md). Кратко: release, прогретый кэш, `/Applications` за 3,0 с и `~/dev` за 4,8 с против 14,7 и 23,1 с в 5c; `~/Library` за 7,4 с (было больше 10 минут).

## Открытое и ограничения

- `place_menu` в ядре выбирает экран по `visible`, а не по `frame`. Курсор в строке меню второго экрана может увести меню на чужой экран. Панели этим не страдают (`place_panel`), ядро в этапе не трогали.
- Второй экран не проверялся (I5b); вместе с S14 этапа 4 и U5 этапа 5.
- M1 на macOS не прогнан.
- Size файла логический, Size папки — место на диске. Для разреженного файла строка показывает логический размер, а папка с ним — меньше.
- Блокирующее чтение сетевого тома не прерывается: отмена срабатывает после него.
- Increase Contrast для тоста и панели не учтён, как и для меню.
