# Orbit: общий план

Orbit (репозиторий FastCompact) — нативное фоновое приложение для macOS на Rust и AppKit (`objc2`). Живёт в строке меню. Жест: выделить файл или папку в Finder, удержать хоткей, получить круговое меню у курсора, навести на сектор, отпустить клавишу, и действие выполнится.

## Цели качества

1. Дорогой вид на macOS: стекло, анимации, нативные символы.
2. Blazing fast: от хоткея до первого кадра меньше одного кадра.
3. Минимум нагрузки: в простое ноль работы, малый RSS.
4. Порт на другие ОС — после MVP. В MVP только macOS.

Когда удобство спорит со скоростью или нагрузкой, выигрывают скорость и нагрузка. Ничего платформенного в `orbit-domain`, `orbit-app` и `orbit-runtime` не добавляется.

## Границы MVP

Жест (режим default):

1. Выделить один файл или папку в Finder или на рабочем столе.
2. Удерживать хоткей Ctrl+Option+Space. У курсора открывается круговое меню с именем объекта.
3. Навести курсор на сектор. Это только подсветка.
4. Отпустить клавишу. Действие запускается, меню закрывается.

Правила:

- Выделение фиксируется в момент вызова. Движение курсора объект не меняет.
- Отмена: Esc или сектор X внизу круга. После отмены отпускание ничего не запускает.
- Отпускание в нейтральной зоне, вне меню или над недоступным действием закрывает меню без операции.
- Один жест запускает не больше одной операции.
- Нужен ввод (например, имя) — круг закрывается, открывается форма: Enter подтверждает, Esc отменяет.
- Новый файл не перезаписывает существующий. Исходник цел.
- Объект определён неоднозначно — сообщить и ничего не делать с другим файлом.

Девять секторов по часовой стрелке с верха: Путь, Сведения, Переименовать, ZIP, X (низ), Resize, В PNG, В JPEG, Reveal.

| Действие | Решение |
|---|---|
| Путь | копирует абсолютный путь |
| Сведения | путь, тип, размер, свойства |
| Переименовать | `.hidden` разрешён, `:` запрещён, занятое имя — ошибка, без нумерации |
| ZIP | файл и папка |
| В JPEG / В PNG | два мгновенных сектора без формы, JPEG с качеством 90; к своему формату неактивны |
| Resize | только JPEG и PNG, только уменьшение, пишется в формате источника, имя `photo 1000x750.png` |
| Reveal | показать в Finder |

Недоступные действия остаются на месте, но неактивны. Под курсором они тускло подсвечиваются (`Highlight::Inactive`), отпускание ничего не делает. Хоткей при открытой форме закрывает форму без операции и начинает новый жест.

Также в MVP: настройка хоткея, проверка разрешений с объяснением, меню в пределах экрана, индикация прогресса, результата и ошибки.

Вне MVP: видео, PDF, группы файлов, пользовательские скрипты, плагины, интеграция с другими приложениями, режим fast (цель под курсором, без выделения). Один объект за операцию.

## Архитектура

```text
orbit-domain → orbit-app → orbit-runtime → orbit-macos → orbit-desktop
```

- `orbit-domain`: модель и чистая логика (цель, действия, операции, геометрия меню). Без AppKit, потоков и IO.
- `orbit-app`: контроллер `AppController::update` (событие → новое состояние и эффекты), состояние, порты `MenuView`, `ParametersView`, `Feedback`, `Shell`.
- `orbit-runtime`: `Runtime`, `run`, `Platform`, потоки resolver и jobs, исполнение эффектов. Тесты на фейковой платформе.
- `orbit-macos`: всё платформенное. Хоткей, `CGEventTap`, чтение выделения Finder через AX, панель, слои, операции с файлами.
- `orbit-desktop`: `main.rs`, логи, блокировка второго экземпляра, выбор платформы.

Первые три crate'а не знают ни об `objc2`, ни о `target_os`; это проверяет `scripts/check-portable.sh`. UI — AppKit и Core Animation, без SwiftUI. Порт на другую ОС — новый crate с `impl Platform` и строка в `orbit-desktop`.

## Сквозные инварианты

- **I1.** Точка курсора фиксируется в хоткей-обработчике на main. Resolver текущий курсор не читает.
- **I2.** Цель — ровно один выделенный объект в области файлов Finder, где фокус. Выделение читается один раз и хранится до конца жеста. Ввод между нажатием и концом чтения → `SelectionUnstable`, тихой подмены A на B не бывает. Отказ всегда с причиной: Finder не активен, фокус вне области файлов, 0 или больше 1 выделенных, нестабильное выделение.
- **I3.** Нажатие и отпускание без движения не выбирает действие, даже если меню сдвинуто от края экрана (порог считается от точки вызова).
- **I4.** Released или Esc во время Resolving закрывает жест. Поздний `TargetResolved` той же сессии игнорируется: проверяется состояние, не только `SessionId`. Конец жеста — отпускание Space или любого модификатора хоткея.
- **I5.** Публикация без перезаписи: временный файл в каталоге назначения и `persist_noclobber`, конфликт → следующий кандидат имени. Rename — через `renamex_np(RENAME_EXCL)`. Смена регистра на APFS — сравнением `FileIdentity`.

Ослаблять инварианты ради упрощений нельзя.

### Что отложено в этапы

- **Этап 7.** Цикл публикации по `NameCandidates`: `AlreadyExists` → следующий кандидат, другая ошибка (в том числе `ENAMETOOLONG`) → стоп, кандидаты кончились → `NoFreeName`. Тест в tempdir: ASCII-имя в 255 байт, кандидат ` 2` даёт `ENAMETOOLONG`.
- **Этап 8.** `ImageFacts.size` считается после EXIF-ориентации, результат пишется повёрнутым.
- **Этап 9.** Эквивалентность имён (регистр, `Σ`/`ς`, NFC/NFD) — через `FileIdentity` назначения. Domain сравнивает имена побайтно. Длину имени проверяет ФС, не domain.
- **Этап 5, продукт.** Увидеть в spike: цвет иконки при подсветке и читаемость на разных фонах, Increase Contrast, haptics (`NSHapticFeedbackManager`), пересчёт цветов при смене темы под открытым меню.

### Итоги spike этапа 5 для продукта

- Стекло: `NSGlassEffectView`. Слои сектора и иконок класть в `NSGlassEffectView.contentView` (координаты от угла диска, центр меню в `(outer, outer)`). Слои в корневом слое окна рисуются под стеклом и размываются. Отдельный `NSView` рядом со стеклом делает всё непрозрачным.
- У слоёв, созданных вручную, `contentsScale = 1`. Ставить `window.backingScaleFactor()` на каждый слой и маски иконок.
- Подсветка — смена `fillColor` готового `CAShapeLayer` в `CATransaction` около 70 мс. Иконка — белый слой с маской из SF Symbol, отрисованного один раз.
- Появление: по умолчанию без анимации. Пружина 700 мс / bounce 0,5 понравилась на глаз; на 150 мс разницы между spring, ease и none не видно.
- Ввод не ждёт анимацию: попадание считает `MenuGeometry::hit` по позиции из tap, не по кадрам.
- Скорость показа: p95 до следующего витка run loop меньше 8 мс (по ручному прогону, без Instruments).

## Как работаем

- Каждый шаг — отдельный коммит от имени пользователя. Push только по просьбе.
- После правок Rust: `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`, `cargo test --workspace --all-features`.
- «Не прогнан» пишем про всё, что не запускалось. Пройденным пункт считается только после результата.
