# Этап 5, шаг 0: spike кругового меню

Одноразовый код, в публичный API не входит: `crates/orbit-macos/examples/spike_ui/`. Он проверяет вид и скорость меню на тех же типах, что пойдут в продукт (`MenuGeometry::standard()`, `MENU_LAYOUT`, `Hit`). Finder, tap и контроллер в нём не участвуют: хоткей открывает меню у курсора, движение мыши подсвечивает сектор, отпускание закрывает и пишет выбранный слот в лог. Что удастся, переедет в `ui/radial_panel.rs` и `ui/radial_view.rs`.

## Запуск

```sh
scripts/bundle-spike.sh --example spike_ui          # ad-hoc подпись: только отладка
ORBIT_SIGN_IDENTITY="Apple Development: …" scripts/bundle-spike.sh --example spike_ui
tail -f ~/Library/Logs/Orbit/spike.log
```

Bundle id тот же, что у spike этапа 0 (`com.example.orbit.spike`), поэтому Accessibility не нужно выдавать заново, если приложение подписано тем же сертификатом. Хоткей — Ctrl+Option+Space.

| Переменная | Значение |
|---|---|
| `ORBIT_SPIKE_UI_BACKGROUND` | `glass` (по умолчанию), `vibrancy`, `plain` |
| `ORBIT_SPIKE_UI_ANIM` | `spring`, `ease`, `none` (по умолчанию) |
| `ORBIT_SPIKE_UI_DURATION_MS` | длительность появления, 700 |
| `ORBIT_SPIKE_UI_BOUNCE` | отскок пружины 0–1, 0,5 |
| `ORBIT_SPIKE_UI_HIGHLIGHT_MS` | смена подсветки, 70 |
| `ORBIT_SPIKE_UI_UNAVAILABLE` | слоты через запятую, нарисованные недоступными, например `5,6,7` |
| `ORBIT_SPIKE_UI_DUMP` | `1`: дерево слоёв панели в лог при старте |

## Устройство

- Панель и все слои создаются один раз в `MenuPanel::new` (на старте ~21 мс в отладочной сборке). На хоткей: `setFrameOrigin`, смена цветов существующих слоёв без неявных анимаций, короткая анимация появления, `orderFrontRegardless`.
- Фон: `NSGlassEffectView` с `cornerRadius` = внешний радиус, либо `NSVisualEffectView` (HUD) с круглой маской слоя, либо плоский диск (`CAShapeLayer`). При Reduce Transparency стеклянный вид скрывается и показывается плоский диск.
- Сектор — `CAShapeLayer` с путём из `MenuGeometry::slot_bounds` (кольцо между нейтральной зоной и внешним радиусом, зазор 0,02 рад). Подсветка — смена `fillColor` в `CATransaction` длиной `HIGHLIGHT_MS`. Акцент берётся из `controlAccentColor`, «Отмена» — `systemRedColor`.
- Иконка — белый слой с маской-символом: SF Symbol рендерится один раз через `CGImageForProposedRect` в 2× и кладётся в `mask.contents`, поэтому цвет меняется без перерисовки.
- Появление: `CASpringAnimation(perceptualDuration:bounce:)` по `transform.scale` 0,92→1 плюс `CABasicAnimation` по `opacity`. Режимы `ease` и `none` — для сравнения. При Reduce Motion анимации нет.
- Попадание считает `MenuGeometry::hit` по позиции мыши (глобальный монитор `MouseMoved`), не кадры анимации.

## SwiftUI-эталон (G10)

Стенд: `scripts/swiftui-ref/` (SwiftPM, вне cargo workspace, не продуктовый код). То же меню на SwiftUI: круг `glassEffect(.regular, in: .circle)`, 9 секторов, SF Symbols, цвета только системными стилями (`.fill.tertiary`, `.fill.quaternary`, `.primary`, `.tertiary`, `.tint`, `Color.red`), палитра Rust не копировалась. Геометрия (28 / 110, зазор 0,02, иконка 20 pt, раскладка символов) скопирована из Rust spike.

```sh
cd scripts/swiftui-ref
swift build
swift run SwiftUIRef --dump-once --appearance light   # или dark; лог: ~/Library/Logs/Orbit/swiftui-ref.log
swift run SwiftUIRef                                  # хоткей Ctrl+Option+Shift+Space, Esc/клик закрывают
```

Переменные: `REF_BACKGROUND=glass|material|plain`, `REF_ANIM=spring|ease|none`, `REF_DURATION_MS` (0, 3000], `REF_BOUNCE` (−1, 1), `REF_HIGHLIGHT_MS` (0, 1000], `REF_UNAVAILABLE=2,3`. Значение вне диапазона или не число заменяется значением по умолчанию с записью в лог (проверено для `REF_BOUNCE=1`, `abc`, `REF_DURATION_MS=0`, `REF_HIGHLIGHT_MS=-5`, `REF_ANIM=wobble`, `REF_UNAVAILABLE=3,99`).

| Метка | Значение |

### Что дал дамп слоёв

- **`CAAnimation` на слоях нет** (наблюдалось, обе темы, 1323 посещения слоёв за прогон): `animationKeys` пуст у всех. SwiftUI меняет `opacity` и `transform` самих слоёв кадр за кадром; модельные и presentation-значения совпадают на каждом снимке, `presentation()` был доступен у всех слоёв. То есть вытащить из SwiftUI кривую как параметры `CAAnimation` нельзя; кривая получена только рядом снимков.
- Слои SwiftUI: `CALayer` (корень диска), `ColorShapeLayer` (сектора), `CGDrawingLayer` и `ColorShapeLayer` (иконки), `CASDFLayer` (стекло). Внутри SwiftUI масштаб применён к слою диска и к слоям секторов и иконок по отдельности, а не к одному контейнеру.

Значения от прогона к прогону слегка плавают, потому что моменты снимков не совпадают до миллисекунды: в таблице фактическое время каждого снимка, а не плановое.

Вывод для продукта (предложение, глазами не проверено): по динамике пружины модели совпадают, брать `perceptualDuration/bounce`. Решение, что нужнее, остаётся за глазами пользователя.

### Подсветка: переход сектора, `withAnimation(.easeOut(duration: 0,07))`

Заливка сектора 1 (акцент) по фактическим снимкам `cacheDisplay`, альфа RGBA без стекла (наблюдалось, светлая тема):

| Момент | Заливка sRGB | Альфа |
|---|---|---|
| до | (0,000, 0,000, 0,000) | 0,047 |
| 18 мс | (0,169, 0,421, 0,744) | 0,176 |
| 45 мс | (0,248, 0,543, 0,947) | 0,635 |
| 71 мс | (0,256, 0,558, 0,971) | 0,941 |
| `completion` ≈ 85 мс | (0,255, 0,562, 0,973) | 1,000 |

Обратный переход: 43 мс альфа 0,518, 71 мс 0,094, конец ≈ 86 мс 0,047. «Отмена» ведёт себя так же. Иконка на подсвеченном секторе в итоге белая (1,000). Переход по пикселям заканчивается около 70–85 мс; `completion` приходит на 85–91 мс. (В предыдущем прогоне те же моменты дали чуть другие числа, например 0,541 на 48 мс: разброс от момента снимка.)

Ограничения, из-за которых числа нельзя считать точными:
- `completion` для подсветки приходит нестабильно: в нескольких прогонах `highlight off` завершился на +5 мс вместо +90 мс (запуски `REF_ANIM=none` и `ease`). Доказательством конца перехода служит ряд пикселей, а не `completion`.
- Заливка при смене стиля идёт кросс-фейдом старого и нового слоя, так что промежуточные значения — смесь двух слоёв (композит), а не интерполяция одного цвета.
- Сравнение с Rust: смена `fillColor` готового `CAShapeLayer` за 70 мс (скопировано из кода spike) даёт монотонный переход одного цвета; сам Rust-переход пикселями не снимался (не удалось измерить в том же виде).

Две оговорки:
- Пиксели читаются из bitmap в пространстве `Color LCD` и переводятся в sRGB. Значения подсветки (0,255, 0,562, 0,973) и красного (0,946, 0,392, 0,343) заметно отличаются от значений из API (0,000, 0,533, 1,000 и 1,000, 0,220, 0,235). Причина не установлена: цветовая обработка при переводе или то, как рисует `.tint`; поэтому цвета подсветки по пикселям переносить в продукт нельзя, брать значения из API.

### Отличия стенда от Rust spike и от продукта

- Ввод: панель не принимает мышь, указатель и клики идут из глобального монитора на время показа; tap, `MenuGeometry::hit` и порог движения I3 не воспроизведены. Подсветка в сценарии идёт через `withAnimation`, на живом наведении — тем же `withAnimation` из монитора.
- Хоткей: Ctrl+Option+Shift+Space (Rust spike: Ctrl+Option+Space), чтобы запускать оба рядом.
- Стенд привязан к macOS 26 (`glassEffect`); выводы не переносятся на другие версии ОС.
- Стекло в `cacheDisplay` не попадает, поэтому альфа в пикселях — только у содержимого, без стекла под ним.
- Esc сделан Carbon-хоткеем на время показа (панель не становится key window и не крадёт фокус).

### Не проверено (за пользователем)

- Esc поверх другого приложения сразу после хоткея, без клика по панели: меню должно закрыться и фокус остаться у приложения под ним.
- Клик вне меню и по самой панели закрывает меню.
- Сравнение глазами рядом с Rust spike: стекло, зазоры, размер и вес иконок, подсветка, появление 700 мс / bounce 0,5.

## Известные ограничения spike

- Палитра строится на каждом показе (`11f5463`), поэтому тема, сменённая пока меню скрыто, подхватывается; смена без перезапуска ещё не проверена руками. Смена темы под открытым меню не отслеживается: динамические цвета (акцент, красный) берутся как `CGColor` в момент показа. Для продукта — пересчёт при `viewDidChangeEffectiveAppearance`.
- Окно не получает мышь (`ignoresMouseEvents`), позиция идёт из глобального монитора. В продукте это место займёт `PointerMoved` из tap.
- Меню не сдвигается от края экрана через `place_menu`: используется простое ограничение по `visibleFrame`, как в spike этапа 0.
- Haptics (`NSHapticFeedbackManager`) не проверялся.
